## 2. M0：工程脚手架与基建（0.5 天）

任务清单：

1. `flutter create --template=package easy_design_system` 生成包骨架（目录沿用 `flutter_easy_design_system`）。
2. `pubspec.yaml`：name、Dart SDK 约束、`uses-material-design: true`、assets 声明默认主题 JSON。
3. `analysis_options.yaml`：`flutter_lints` + 附加严格规则（prefer_const_constructors 等）。
4. `lib/easy_design_system.dart` 总出口（先空实现占位）。
5. 复制资源与 Fixture：`EDSDefaultTheme.json` → `lib/assets/`；3 份 Fixture JSON → `test/fixtures/`（直接从 Swift 仓库复制，字节一致）。
6. GitHub Actions：`analyze + format --set-exit-if-changed + test`（主线 stable；ohos fork 由本机验证）。
7. `example/` 骨架：`flutter create` App + 侧边栏导航空壳。
8. README 初版（愿景 + 快速开始占位）、CHANGELOG（Keep a Changelog 格式）、LICENSE（沿用 Swift 仓库协议）。

验收标准：

- `flutter analyze`、`flutter test`、`dart format` 在 CI 全绿。
- example 可在 macOS 桌面端启动显示空壳。

## 3. M1：Token 系统与主题机制（1.5 天）

任务清单：

1. `EdsColorHex`：`parseHex`（#RGB/#RRGGBB/#AARRGGBB/#RRGGBBAA 四格式 + 显式 format 参数）与 `toHex(Color)`；非法输入回退 `#000000`（对齐 Swift 行为）。
2. 9 组子 Token 类：字段名、默认值与 Swift 逐一对齐；`copyWith`、`==`、`hashCode`。
3. `EdsColorScheme.resolve(tokens, brightness)`：派生色亮暗表（§5.2 方案）。
4. `EdsDesignTokens.fromJson/toJson`：JSON key 与 Swift `CodingKeys` 逐字节一致；缺失字段回退默认；导出 prettyPrinted + key 排序（对齐 `sortedKeys`）。
5. `EdsPresetTheme`：default/blue（别名）/orange/purple + `allPresets`；语义色 hex 与 Hero 渐变与 Swift 相同。
6. `EdsTheme.instance`：`update()`、`applyPreset()`、`configureJsonString/File/Asset`、`exportJsonString()`；内部 `ValueNotifier` 支撑运行时刷新（§5.3）。
7. `EdsThemeScope`（InheritedWidget）+ `context.edsTokens` 扩展；局部优先、全局回退；`==` 判定避免无效重建。
8. `EdsApp` 便捷根组件（可选）：统一接 `platformBrightness` + 全局主题监听。
9. 单测：方案 §12 的 #2/3/4/5/6/7 六组（含 3 份 Fixture 契约）。

验收标准：

- Swift 版 `EDSDefaultTheme.json` 与三份 Fixture 在 Dart 侧解码结果逐字段正确。
- tokens 修改 → `EdsThemeScope` 下组件自动重建（widget 测试断言）。
- `exportJsonString()` 输出可直接被 Swift 版 `configure(jsonData:)` 加载。

## 4. M2：Easy API 与自适应层（1.5 天）

任务清单：

1. `EdsStyle/EdsSpace/EdsWidth/EdsVisibility/EdsOptions` 类型。
2. `EdsEasyRecipe.resolve` 纯函数：六场景基线配方 + 三类覆盖规则（逐条移植，含 fixed 负数夹 0、visible 升级规则）。
3. `EdsInteractionProfile`（automatic 解析规则表）+ `EdsInteractionProfile.of(context)` 与覆盖 Scope。
4. `EdsSizeClass`（600 断点）+ `EdsSizeClass.of(context)`。
5. `EdsResolvedMetrics.resolve`（pagePadding 回退、触控目标、hover 开关、persistent 辅助动作）+ `interactiveHeight()`。
6. `EdsEasy` Widget：padding → width → `EdsSurface` → `EdsThemeScope` 重注入 → DefaultTextStyle/IconTheme 覆盖。
7. `Widget.easyDesign(...)` / `Widget.easyDesignTheme(...)` 扩展。
8. `EdsFontRole` → `TextStyle` 工厂（含 weight 字符串映射、mono fontFamily fallback）+ `Widget.edsFont()` 扩展。
9. `EdsSurface` + `EdsSurfaceConfiguration`（背景/圆角/边框/BoxShadow；null background 短路）。
10. 单测：方案 §12 的 #8/9/11/12 四组。

验收标准：

- Recipe 断言与 Swift `EasyDesignSystemTests` 的 #8/9/11/12 数值完全一致。
- 同一份自定义 spacing/radius token 下，六场景渲染结构正确（widget 测试）。

## 8. 版本与 Git 策略

- 语义化版本：`0.x` 阶段 minor = 新组件/能力，patch = 修复与微调；`1.0.0` 条件 = 组件全量 + API 基线冻结 + pub.dev 发布。
- 分支：`main` 常绿（CI 通过才合入）；每里程碑结束打 tag；功能分支 `feat/m1-tokens` 命名。
- 公开 API 兼容：V1 用"签名冒烟测试"固化（每次新增公开符号同步登记到 `docs/API_BASELINE.md`），公开 API diff 工具列入 V2。

## 9. 风险跟踪

| 风险 | 影响里程碑 | 缓解 |
| --- | --- | --- |
| 亮暗语义色默认值观感不佳 | M3/M5 | 常量集中一处；M5 走查时统一调优 |
| 大字号布局破坏 | M3/M4 | Row 竖排规则 + Catalog 200% 预览页 |
| hover 误触发（触屏） | M3/M4 | 仅 pointer/hybrid 档案启用 |
| ohos fork 与主线 API 差异 | 全程 | 纯 Dart 无平台通道；CI 用主线 stable |
| 组件数量多导致 M3/M4 超期 | M3/M4 | 组件实现模式统一（读 tokens → 组合基础件 → 测试），同类组件批量化；必要时 M4 后移 Pill 排序等次要特性 |

## 11. 与 Swift 仓库的持续同步

- 迁移基线锁定 Swift 包当前 main（0.3.x，2026-09-21）；后续 Swift 包演进（如新组件、`.done` 类调整）通过 CHANGELOG 对照表人工评估是否同步。
- JSON 主题格式是两边共同契约：任何一侧修改 schema 必须双侧同步并在差异报告登记。
